# ハードウェア：何を買い、どう配線し、まず何を直すか

[English](../en/hardware.md) · [中文](../zh/hardware.md) · [**日本語**](hardware.md)

一式に必要なハードウェアは 4 点だけです。合計してもノート PC 1 台分にも満たない程度です（Orin 本体を除く）。ただし、**次の 3 つを直さないと、そのあとのソフトウェア調整はすべて無駄になります**。これらはエラーを出しません。VAD のしきい値（threshold）を狂わせ、ASR の segmentation を崩し、キャプチャカードを真っ黒にするだけです。

## 1. 部品リスト

| 品目 | 型番 / 仕様 | 役割 | 備考 |
|---|---|---|---|
| 計算ユニット | Jetson AGX Orin 64GB 開発キット | ASR / OCR / TTS / 35B-A3B を実行 | 32GB 版でも 35B は動くが、システムとメモリを取り合う |
| HDMI キャプチャカード | MacroSilicon **MS2109**（`534d:2109`） | デモ機の画面を UVC カメラに変換 | ドライバ不要で安価。1080p30 で安定 |
| USB ヘッドセット | Logitech **H340** | 収音 + ローカルモニタ | モノラルマイク + 3.5mm ジャック。USB 1 本で完結 |
| 外付け SSD | USB3 SSD なら何でも、128G 以上 | モデル（3.4G）+ 35B の重み（22.9G）を置く | ルートディスクは数 G しか空いていないことが多い。無理に詰め込まない |
| HDMI ケーブル ×2 / 分配器 | — | デモ機 → キャプチャカード → プロジェクタ | 分配器がないと「投影しながらキャプチャ」はできない |

システム：**JetPack 7.2.1 / Ubuntu 24.04 / Python 3.12**。JetPack 6.x（22.04 / Python 3.10）でも動きますが、`pyopenjtalk-plus` と `tensorrt` の wheel は別バージョンに差し替える必要があります。[models.md](models.md) を参照してください。

## 2. 配線

```
                 ┌────────────────────────┐
   デモ機 HDMI ──┤ HDMI スプリッタ        ├─→ プロジェクタ / 大画面
                 └────────────┬───────────┘
                              │ HDMI
                 ┌────────────┴───────────┐   USB   ┌──────────────────────────┐
                 │ MS2109 キャプチャカード├────────→│                          │
                 └────────────────────────┘         │  AGX Orin 64GB           │
                 ┌────────────────────────┐   USB   │                          │
                 │ H340 ヘッドセット      ├────────→│  :8095 音声アシスタント  │
                 └────────────────────────┘         │  :8096 会議字幕          │
                                                    └──────────────────────────┘
```

- キャプチャカードは**本体の USB に直接挿す**。ドック経由は不可。以前ハマった例：ドックの給電が足りず、数時間動かしたあとに `/dev/video0` が落ちた。`v4l2` には見えているのに、読み出すとすべて黒フレームだった
- H340 の 3.5mm ジャックにはヘッドホンを挿してモニタできます。ヘッドホンを挿さないと、**スピーカーの音が自分のマイクに拾われ**、自分で自分を呼び出してしまうことがあります（[troubleshooting.md](troubleshooting.md) 参照）

## 3. 先にやるべき 3 つ

### 3.1 60Hz のハム（やらないと VAD のしきい値が全滅）

実測のノイズフロアは **−30.6 dBFS**、スペクトルの最大ピークは 60Hz で 120Hz の高調波があり、0〜80Hz がエネルギーの 38% を占めます。これは部屋の騒音ではなく、電源ハム／グラウンドループです。150Hz の 4 次ハイパスフィルタを入れると：

| | ハイパス前 | ハイパス後 |
|---|---|---|
| ノイズフロア | −30.6 dBFS | **−48.8 〜 −56.6 dBFS** |
| 音声区間の SNR | 9.8 dB | **34 dB** |

音声の主要帯域は 300Hz〜3kHz なので、150Hz 以下を切っても ASR にはまったく影響しません。コードは既定でハイパスをかけます（`voice_probe.py` の `highpass()`）。**自分で収音コードを書く場合は自分で入れてください**。

### 3.2 キャプチャゲイン（H340 は出荷時がフルスケール）

H340 のキャプチャゲインは出荷時 `44/44 = +8dB` で、実測では 33 サンプルがクリップしていました。

```bash
amixer -c 0 cset numid=4 32     # 44 → 32、つまり +8dB → 0dB
amixer -c 0 cset numid=4 44     # 元の値に戻す
```

注意点：このコントロールには `Playback/Capture` のプレフィックスが**ありません**。`amixer sget 'Mic Capture Volume'` は見つからないとエラーになります。必ず `numid` を使ってください。まず `amixer -c 0 contents | grep -A2 numid=4` で確認します。

### 3.3 キャプチャカードのウォームアップ黒フレーム（やらないと最初の 1.2 秒が真っ黒）

MS2109 は `open()` のたびに、しばらく**全黒またはノイズだらけのフレーム**を出力します。数フレーム捨てるだけでは足りません。ノイズフレームは画素の標準偏差が 0 ではないため、「std で全黒かを判定する」と映像ありと誤判定します。

正しい方法（`vision.py` に実装済み）：**40 フレーム連続で捨ててから**判定を始めます。1080p30 なら約 1.3 秒です。したがって「画面をちらっと見る」の所要時間には、常に約 1.2 秒のウォームアップが含まれます。**常駐させてフレームを取り続ける**（ウォームアップのコストを 1 回だけ払う）ことが 2026-11-21 の主要な最適化のひとつでした。[engineering-log.md](engineering-log.md) を参照してください。

## 4. 音声経路（PipeWire）

収音も再生も PipeWire を通します。理由は実用的で、**PipeWire は複数のクライアントが同じ source を同時に読める**からです。`arecord` を直結すると「デバイスがビジー」で失敗します。したがって：

```bash
# 収音（排他なし）
pw-record --target <source> --rate 16000 --channels 1 - > /dev/null

# 再生（出力先を指定する。指定しないと音が HDMI に飛ぶ）
pw-play --target <sink> out.wav
```

現在どのノードがあるかを確認します：

```bash
pactl list short sources    # 収音：USB3.0 Capture / H340 を探す
pactl list short sinks      # 再生：H340 の analog-stereo を探す
```

ノード名は長い（`alsa_output.usb-...H340-00.analog-stereo`）ので、サービスには `--local-sink` で渡します。**ハマった点**：`--target` を指定しないと、PipeWire は既定の sink に音を送ります。その既定 sink が HDMI だと「再生しても無音」になりますが、実際は音がディスプレイに飛んでいるだけです。

> systemd からサービスを起動する場合、`pw-play` / `pw-record` には `XDG_RUNTIME_DIR=/run/user/<uid>` が必要です。ないと**静かに失敗します**（エラーは出ず、音が出ないだけ）。unit にはすでに書いてあるので消さないでください。
