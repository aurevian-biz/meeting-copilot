# トラブルシュート：モジュールで推測せず、症状から引く

[English](../en/troubleshooting.md) · [中文](../zh/troubleshooting.md) · [**日本語**](troubleshooting.md)

ここに挙げたものはすべて実際に踏んだもので、しかも**その多くはエラーを出しません**。
静かな失敗は、エラーよりずっと時間を食います。

## 1. ページが「连接中…」で止まる／dB が -99／ボタンがすべて無反応

まず `/api/status` を見ます。サーバー側にデータがあり、段数が増えているなら、**ページの
スクリプトがそもそも動いていない**ということです。表示されている値は HTML に直書きされた
初期値であって、「SSE がつながらない」わけではありません。

```bash
curl -s localhost:8096/api/status          # サーバーは生きているか？
.venv/bin/python test_caption_pipe.py      # test_page_js_syntax が node --check を実行する
```

よくある原因は `PAGE` 内の JS 構文エラーです（Python の非 raw 文字列が `\n` を食ってしまう）。
フロントエンドを直したら：**サービス再起動 + ブラウザで F5**。`PAGE` は定数なので、
サービスを再起動してもブラウザ側の HTML は更新されません。

## 2. サービスは起動したのに音が出ない／録音されない

| 確認 | 原因 |
|---|---|
| unit に `Environment=XDG_RUNTIME_DIR=/run/user/<uid>` があるか | 欠けると `pw-play` / `pw-record` が**静かに失敗**します |
| `pactl list short sinks` で既定 sink が HDMI になっていないか | 音がディスプレイに流れています。`--local-sink` で H340 を指定します |
| `arecord` が「设备忙」と言う | `--backend pw` に変えます。PipeWire なら複数クライアントが同じ source を読めます |
| ブラウザで最初だけ音が出ない | 自動再生ポリシーに止められています。読み上げ自体はローカルの `pw-play` を通るので、ページ上で一度クリックしてください |

## 3. systemd

| 症状 | 対処 |
|---|---|
| `stop` したら `failed` になる | `caption-bench` には `TimeoutStopSec=20` が必要です。ないとキャプチャスレッドが 90 秒まで引っ張られて SIGKILL されます |
| `NRestarts` が増え続ける | `ActiveEnterTimestamp` を見て、再起動を繰り返していないか確認します。自分の ssh を殺す `pkill -f` も再起動を装います |
| Magnitude が無限に再起動する（数千回） | 手動起動した dockerd の pidfile が systemd を妨げています。手動プロセスを止め、socket/pid を消してから systemd に戻します |
| `pkill -f 'dockerd --config-file ...'` で ssh まで死んだ | 文字クラス `daemo[n].json` を使い、自分のコマンドラインに一致しないようにします |

## 4. OCR／画面を見る

| 症状 | 原因 |
|---|---|
| 最初の 1.2 秒が真っ黒／ノイズ | MS2109 のウォームアップフレームです。判定前に**40 フレーム捨てる**必要があります（ノイズがあると `std ≠ 0` になるので、数フレーム捨てるだけでは足りません） |
| 画面を 1 回見るのに 3.4〜3.9 秒かかる | 正常です：ウォームアップ 1.2 秒 + OCR ≈ 行数 × 30ms |
| OCR が突然 5〜10 倍遅くなる | `cuda-python` のバージョンが JetPack と合っていません → TensorRT が静かに CPU にフォールバックし、ログには一言も出ません |
| 画面は変わったのに文字が更新されない | `/api/look` は内部で指紋（フィンガープリント）でキャッシュしており、同じ画面は再計算しません |
| 語彙に自分の字幕が混ざる | 字幕ページがその画面に映っています。「直近 30 条の字幕と 8 文字の共通部分文字列があれば行を捨てる」処理を入れてあります |

## 5. 自分で自分を起こしてしまう

ヘッドセットの**スピーカー出力をマイクが拾い**、ウェイクワードを発火して自励発振することが
あります。ヘッドセットを着けるか、ローカルモニタ（ページ上の「听 HDMI」）を切ってください。
スピーカーをマイクの隣に置かないことです。

## 6. 翻訳品質

| 症状 | 対処 |
|---|---|
| 出力が日中混在する／スペイン語の単語が出る | 35B-A3B に替えます。7B はこの system では必ず起きます |
| 35B の出力が思考だけで `content` が空文字列 | Qwen3.5 のテンプレートは既定で thinking が有効です。`enable_thinking=false` が必須です |
| 中国語／日本語の指示が効かない | 言語指示は **system と user の両方に付ける**必要があります（system だけなら 0/6、user だけなら 6/6） |
| モデルが「屏幕文字」を勝手に引用する | OCR がないときは動的な system を使い、その単語に一切触れないようにします |
| 半文が完結文に訳される／主語が補われる | 断句が調整できていません。まず `wav_seg_ab.py` で ASR テキストの完全性を見ます |
| 訳文が半分しか出ない | SSE ストリームが単調に伸びる前方一致になっているか確認します。`tools/sse_regress.py` は後戻り 0／空化 0 を専門に見ます |

## 7. 長い文が前の行を押し出してしまう

初期は全量 `innerHTML` + ピクセル単位の `scrollY` 復元でした。長い訳文が 1 文字ずつ高くなる
最中にアンカーがずれ、同じ y が別の内容を指してしまいます。現在は**常駐 DOM の増分更新**に変え、
`#main{overflow-anchor:none}` を指定しています。
逆順（最新が最上部）ではスクロール補正の符号は `+` です。一度逆に書いたことがあり、
`node tools/dom_render_test.js` でカバーしています。

## 8. バグとして追わないもの

- `q_tr` が上がって初めて本当に追いつけていない。`lag_ms` だけが少し高いのは断句の締めのことがある
- 断句の良し悪しは**ASR テキストが文になっているかだけ**で見る。「無音カットの割合」は見ない
- 最初の文字まで 200ms がハードフロア。`TTFT ≈ 65ms + 4.5ms × 新規トークン`
- 短いプレフィックスでは `cache_n` が 0 のまま。キャッシュが壊れているのではなく、ユーザー内容が毎文変わるため
- vLLM は 35B のプレフィックスキャッシュに当たらない（1056 トークン粒度）
- キャプチャカードはドッキングステーション経由で一度落ちた。長時間運用なら本体の USB に直挿しする
- 画面語ヒントの `hits=0` は、画面の内容が会議と無関係なことが多く、機能不全ではない

## 全体を 1 行で見る

```bash
bash scripts/healthcheck.sh
```

サービス、ポート、デバイス、モデル、そして `q_asr / q_tr / dropped / ttft / screen` を順に
報告します。**まずこれを実行し、それからログを読みます。**
