# 使い方

[English](usage.md) · [中文](usage.zh.md) · [**日本語**](usage.ja.md)

## 会議字幕（8096）

`http://<デバイスIP>:8096` を開き、右上の **开始 / 停止 / 清屏**（開始 / 停止 / クリア）を押します:

- **开始 / 停止**: 収音と断句を制御します。`clear` は行を消して seq をリセットします（フロントエンド側でもローカル DOM を空にします）
- **听 HDMI**（HDMI を聴く）: キャプチャカードで受けた音をヘッドホンに戻します。会議中のモニター用です
- **音量条 / dB**（音量バー / dB）: リアルタイムのレベルとしきい値。バーが緑になれば、しきい値を超えて音が出ています
- **状态灯**（ステータスランプ）: `连接中…`（接続中…）→ `运行中` / `已停止` / `断开`
- **屏幕 N 词 · 命中 M**（画面 N 語 · ヒット M）: マウスを載せると、語彙のサンプル、直近のヒット、画面 1 回分の所要時間が見られます
- **最新一条在最上**（最新が最上部）: 下書き行が最上位を占めるため、履歴をさかのぼっている最中に新しい行で押し出されることはありません

### 画面が反応しないときの切り分け順

ステータスランプが「连接中…」のまま、dB が `-99`、セグメント数が `0`、ボタンを押しても無反応 —— これらの値はすべて HTML に直書きされた初期値です。つまり**スクリプトがそもそも実行されていません**。ネットワークの問題ではありません。次の順に確認してください:

1. `curl -s localhost:8096/api/status` にデータが返るか（サーバーが生きている ≠ ページが生きている）
2. ブラウザのコンソールに `SyntaxError` が出ていないか
3. `.venv/bin/python test_caption_pipe.py`（このうち `test_page_js_syntax` は `node --check` を実行します）
4. フロントエンドを変更したら **F5**: `PAGE` はモジュールレベルの定数なので、サービスを再起動してもブラウザの HTML は更新されません

## 音声アシスタント（8095）

`http://<デバイスIP>:8095` を開きます:

- ボタンを押してそのまま話すか、ウェイクワード **「小八你好」**（シャオバー、こんにちは）で常駐リスニングを起動します
- 播報中に話しかけると割り込みます（`barge-in`）。回り込みでは誤発火しません
- **「看屏幕」**（画面を見る）ボタン、または音声での質問で OCR を 1 回実行し、画面の文字を LLM に渡します
- ブラウザは初回に**手動で 1 回クリック**しないと音を出せません。自動再生ポリシーに止められるためです。播報はローカルの `pw-play`（`--local-speak`）を通るので、ブラウザの自動再生には依存しません

## よく使うパラメータ

### 字幕の断句（既定値は実測で合わせ込んだものです。気軽に変えないでください）

| パラメータ | 既定値 | 説明 |
|---|---|---|
| `--max-s` | 6.0 | 強制カットの上限。4.5s では 26% のセグメントが途中で切れます（「大会」が真っ二つになります）。**7s を超えるとハルシネーションが出ます** |
| `--hold` | 0.45 | 基準の無音しきい値。段階的なポーズには別途 `--hold-short 0.3` / `--hold-long 0.9` があります |
| `--seg-mid` / `--seg-long` | 1.2 / 2.4 | 短文・中文・長文でポーズのしきい値を使い分けます |
| `--soft-cut` | 0.7 | 強制カットの前に、末尾をさかのぼってエネルギーの谷を探す探索窓（秒） |
| `--min-s` | 0.25 | これより短いものはそのまま捨てます（クリック音、咳） |
| `--ctx-lines` | 1（unit 内） | 上文の行数。毎文変わるので、削ると約 90ms 節約できます |
| `--tr-workers` | 1（unit 内） | worker を増やしても単文のレイテンシは変わらず、VRAM の取り合いが増えるだけです |
| `--tr-prompt` | full | 短い版のほうがむしろ遅くなります。[llm-serving.ja.md](llm-serving.ja.md) を参照してください |
| `--screen-hints` / `--screen-every` | オフ / 15s | 必要時のみの画面語ヒント。下記を参照してください |
| `--wav` | — | 収音せず、wav ファイルを直接流します（断句の問題をオフラインで再現） |

### 画面語ヒント（任意）

`--screen-hints` を有効にすると、`--screen-every` 秒ごとに voice-bench の `/api/look` へ OCR を 1 回要求し、候補語を抽出します。**この文の ASR テキストに「読みが似ていて表記が違う語」が現れたときだけ**、翻訳にヒントを 1 つ渡します:

```
【屏幕词】「畔蒜泰助」——本句的「阪井泰介」若指同一事物，请改用屏幕写法。
```

（ヒントの文面自体は中国語で出力されます。）

- ヒット時は約 +25 token（+65ms）で、支払いはそのセグメント分だけです。ヒットしなければ token は 1 つも増えません
- **画面の文字を丸ごと翻訳に詰め込まないでください**: 実測で +70 token / +250ms、しかも 6 文中 3 文が悪化しました（私たちの字幕ページ自体が画面に出ているため、自己ループします）
- 上限は「固有名詞の同音誤字」です。通常の聞き間違い（`つぶさに` → `つぶさんに`）は救えません
- ラテン語の単語を語彙に入れないでください: OpenJTalk が 1 文字ずつ読んで 50 モーラになり、永遠に一致しません

## 状態の見方

```bash
curl -s localhost:8096/api/status | python -m json.tool
```

主要なフィールド:

| フィールド | 意味 | 健全な値 |
|---|---|---|
| `q_asr` | ASR 待ちのセグメント数 | 0 |
| `q_tr` | 翻訳待ちのセグメント数 | 0。**増加 = 翻訳が追いついていない** |
| `dropped` | キューから捨てられたセグメント数 | 0 |
| `ttft_ms` | 訳文の首字レイテンシ | 400~600ms |
| `trans_ms` | 文全体の翻訳完了 | ~1000ms |
| `lag_ms` | 端到端レイテンシ | ~290ms |
| `screen` | 語彙リストの状態 | `terms / hits / polls / last_ms / last_err` |
| `monitor` | 再生の状態 | `on / starts / error` |

全体像は 1 コマンドで確認できます: `bash scripts/healthcheck.sh`。

## オフライン再現

マイクに向かって何度も話したくないときは、wav ファイルで同じ断句チェーンを走らせます:

```bash
.venv/bin/python caption_server.py --wav sample.wav --no-draft
.venv/bin/python tools/wav_seg_ab.py --wav sample.wav --a 0.45 --b 0.7
.venv/bin/python tools/sse_regress.py     # データ層: リグレッション 0、空 0
```
